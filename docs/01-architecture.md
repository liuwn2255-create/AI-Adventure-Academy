# 系統架構與技術選型

## 產品基線

- 對象：以國小三年級為起點；年級、學期與能力範圍須由課程審查者確認。
- 學習領域：數學、國語文、自然科學及思考訓練。思考訓練作為跨領域活動設計，不擅自宣稱為獨立正式領域或課綱代碼。
- 視覺：明亮低多邊形 3D。
- 輸入：鍵盤與手機觸控。
- 保存：瀏覽器 `localStorage` 本機保存；清除瀏覽資料或換裝置可能失去進度。
- AI：先採用可預期的固定規則；後續才評估 Cloudflare Worker AI。

## 邏輯架構（規劃）

1. **呈現層**：適配桌面與手機的遊戲畫面、HUD、題目及回饋介面。
2. **輸入層**：將鍵盤與觸控轉成一致的移動、互動及選答命令。
3. **遊戲流程層**：管理場景、關卡狀態、題目流程、通關及重試。
4. **內容層**：載入經驗證的題目與關卡資料；內容記錄課綱追溯與審查狀態。
5. **規則回饋層**：先以明確答案、規則與預先審核解釋提供回饋。
6. **保存層**：以版本化的進度資料寫入 `localStorage`，載入時驗證並處理舊版本。
7. **選配服務層（未實作）**：日後才透過 Cloudflare Worker 提供 AI 請求代理。AI 不得決定正確答案、分數、重複計分去重或關卡通關狀態；這些由固定規則判定。AI 只可提供非權威輔助說明，且發生關閉、逾時、錯誤或無效輸出時需回退到可獨立完成的固定規則流程。

## 技術選型原則

本次未發現程式碼或套件設定，故不宣稱專案已採用任何框架、3D 引擎或建置工具。階段 1 前應比較能支援瀏覽器 3D、鍵盤/觸控、可部署靜態資產及可測試性的方案，並記錄決策與版本。課程及題目資料採可版本控制的 JSON；在沒有必要前不引入資料庫或伺服器端帳號。

## 品質與安全約束

- 所有互動需支援鍵盤與觸控，並有明確焦點、提示與可讀回饋。
- 題目資料在載入或建置階段通過結構與語意驗證。
- `localStorage` 讀寫失敗時不得讓遊戲崩潰；提示保存不可用並允許本次遊玩。
- 不將 API 金鑰或秘密放在前端。若日後採 Worker，需由伺服器端管理秘密、限制輸入及錯誤回退。
- AI 回應需視為不可信內容，且不得覆蓋已審核的題目正解。
