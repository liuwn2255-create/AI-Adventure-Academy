# 課綱追溯與審核方法

## 依據與現況

正式依據限定為教育部發布的十二年國民基本教育課程綱要及國家教育研究院提供的正式課綱資料。逐份可直接查閱的官方文件、發布資訊、頁節及本輪核對範圍見 [`curriculum/sources.json`](../curriculum/sources.json)。本輪確認國語文第二學習階段閱讀學習表現與篇章學習內容、數學三年級容量學習內容及其第二學習階段表現、自然科學第二學習階段觀察表現及動物外形學習內容。確認範圍與未確認項目分列於 [`curriculum/curriculum-map.json`](../curriculum/curriculum-map.json)。

「第二學習階段」涵蓋國小三、四年級，該階段學習表現不得改寫成三年級單獨要求。數學內容碼 `N-3-15` 明確屬三年級內容；另兩領域已定位的 `Ⅱ` 條文仍是階段層級。領綱本身不足以確認個別學校三年級實際採用教材、學期先後及教學進度，相關欄位仍標為待核對。

`curriculum/curriculum-map.json` 分列已有官方條文定位的學習重點與待核項。已定位的條文仍須由課程專業人員簽核，並不自動構成題目或三年級教學安排的核准。任何未在官方文件中確認的正式代碼不得填入；暫以 `pending_review` 表示。

## 追溯流程

1. 從官方來源取得並確認正式發布版本與適用修正令。
2. 由課程審查者定位課綱原文，記錄文件名稱、來源 URL、頁碼或節次及查核日期。
3. 將遊戲中的學習目標連結到該原文；若無法定位，保持 `pending_review`，不得推定代碼。
4. 對每一道題目記錄一項或多項已核對的課綱對應，並核對答案、解釋與年級適切性。
5. 題目依 schema v2 記錄專案單元 `unitId`、正整數 `unitRevision` 及題目自身的正整數 `revision`。`unitId` 必須查 docs/18 規定的獨立單元登錄，不能拿課綱地圖 ID 代替；`unitRevision` 固定題目所依據的單元版本，題目 `revision` 版本化題目本身，兩者不可互換。新題目發布及新關卡使用只接受目前核准的單元 revision；不得將舊題目自動改綁新版。
6. 對每個題目 revision 分別留下課綱對應、三年級適切性、答案正確性及解說品質審查，記錄審查者、角色、日期、題目 `revision`、所依據的 `unitRevision` 及結論。課綱 mapping 的官方條文核對狀態不是題目審查結論；課綱地圖的 `verified` 類狀態不代表教師或課程專業人員已簽核。
7. 正式發布者另行核對該題目 `revision`、固定的 `unitId`／`unitRevision`、資料完整性及發布條件，記錄發布者、發布日期與題目 revision；只有發布狀態為 `published` 且單元版本追溯有效的題目可由正式關卡引用。關卡引用必須固定題目 ID 與題目 revision，並由題目資料解析到有效的單元 revision。

## 必填追溯欄位

`curriculum-map.json` 的每個重點應保留 `status`、`sourceId`、`performanceCodes`、`contentCodes`、`sourceUrl`、`documentTitle`、`pageOrSection`、`gradeRange`、`stagePerformanceRange`、`reviewer`、`reviewDate`。`sourceId` 若非空，必須存在於來源登錄。待核對代碼或頁節不得推測；未確認時維持 `pending_review` 並使用空代碼陣列或 `null`。思考能力若作為遊戲設計標籤，不能冒充正式領域或課綱代碼；須另找到其實際承載的已核實課綱重點，或不宣稱課綱對應。

## 每題發布門檻

題目需同時通過課綱對應審核、三年級年級適切性審核、正確答案審核及解釋審核。四者任一缺漏、狀態非通過或來源定位不明，禁止正式發布。審核紀錄應能回溯至題目版本與審查日期。條文是否對應三、四年級階段範圍，與題目是否適用三年級實際進度，是兩項不同審查。

schema v2 題目資料另須具備 `unitId`、`unitRevision`、題目 `revision`、`prerequisites`、`curriculumMappings`、`textbookEvidence`、四項審查及發布紀錄。題目審查紀錄的 `revision` 必須等於題目自身 revision，`unitRevision` 必須等於題目固定引用的單元版本；單元 schema、狀態、歷史及簽核要求以 [單元登錄規格](18-unit-registry-spec.md) 為唯一依據。課綱證據回答「官方條文是否支持此學習目標」；教材證據回答「題目主張依據哪一版本教材及可定位內容」；題目審查回答「指定題目及單元版本下的課綱對應、年級適切性、答案及解說是否合格」。三者不可互相替代。第二學習階段指標只表示三、四年級階段要求；出版社公開簡介只可作教材背景，均不可證明指定班級已完成授課。

指定班級使用須有獨立紀錄，至少連結 `questionId`、題目 `revision`、`unitId`、`unitRevision`、`cohortId`、`schoolYear`、授課狀態、逐項先備能力確認、實際授課紀錄位置、任課教師姓名與職務、確認日期及意見。此題目／班級紀錄須與 docs/18 定義的單元層級班級授課紀錄分開保存；教材證據不可冒充 lesson record。只有所需先備能力均有具體實際授課證據且經任課教師或學校指定人員確認，才可標記 `ready_for_class`。正式發布者紀錄（發布者、日期、題目 revision）與內容審查者紀錄分開；題目 `approved` 不等於 `published`，題目已發布也不代表任何班級已可使用。

題幹、選項、正確答案、解釋、`unitId`／`unitRevision`、課綱連結或教材證據有實質變更時，須建立新題目 `revision`、保留舊版紀錄並重新執行相關審查；題幹、選項、答案或解釋變更須重做四項審查。單元範圍、課綱對應、年級或教材依據實質變更時，依 docs/18 建立新單元 revision，既有題目不自動改綁；受影響題目須評估並在需要時建立新題目 revision、重新審查及發布。此為文件規格，並不表示題目驗證器或發布流程已實作。
