# 關卡資料格式、流程與通關條件

本文件定義未來關卡資料與發布門檻，不表示已有遊戲、關卡載入器或程式防護。

## 建議關卡資料格式

```json
{
  "schemaVersion": 1,
  "id": "island-01",
  "title": "關卡標題",
  "gradeRange": [3, 3],
  "learningObjectives": ["objective-id"],
  "interactions": [
    {
      "id": "gate-01",
      "type": "question_gate",
      "questionRefs": [
        { "questionId": "example-question-001", "revision": 1 }
      ]
    }
  ],
  "completion": { "requiredInteractionIds": ["gate-01"], "minimumCorrect": 1 },
  "assets": [],
  "status": "draft"
}
```

此範例只示意資料結構。關卡不可使用未實際存在或未核准的題目；座標、資產與其他引擎欄位須待技術棧選定後再定義。

## 關卡引用與發布門檻

- 可發布關卡只能引用 `publicationStatus: "published"` 的題目，並須精確引用其 `questionId` 與題目 `revision`。題目本身還必須同時記錄 `unitId` 與 `unitRevision`；題目 revision 與單元 revision 是不同版本軸，不得互相代替。
- 每個題目 revision 必須有 `curriculum`、`gradeLevelFit`、`answer`、`explanation` 四項通過紀錄，且審查 revision 與引用版本一致。候選草稿、待審、退回、核准但未發布及作廢題目均不得進入正式關卡。
- 關卡發布驗證必須解析題目固定引用的 `unitId`／`unitRevision`，並在單元登錄（欄位與歷史格式依 [`docs/18-unit-registry-spec.md`](18-unit-registry-spec.md)）確認該版本及其歷史快照存在、完整且一致。新題目發布及新關卡發布／使用只接受目前 `status: "approved"` 的單元 revision；`candidate`、`in_review`、`retired` 及已被新版取代的歷史 revision 不得新引用。舊題目或舊關卡不得自動改綁新版；重新發布或建立新關卡前須按單元影響評估處理並重新驗證。
- 關卡發布驗證必須拒絕不存在、未發布、作廢、revision 不符、審查未完成、單元版本不存在／無效、年級不相容或題型不受支援的引用；不得靜默略過、以其他題目或單元版本替代或繼續發布。若無法證明所指單元版本存在，拒絕發布及執行載入。
- 題庫全域發布不代表任一班級已教該內容。指派給指定班級前，須同時確認該班實際授課紀錄及單元／題目所需先備能力；教材證據只證明教材來源、版本、冊次、單元與頁次，不能代替班級授課紀錄。未有具名任課教師或學校指定人員、授課紀錄與日期的確認時不得指派該班。班級確認不得回寫成全域題庫的課綱或內容核准。
- 已發布關卡固定題目版本。題目新 revision 不會自動改變既有關卡引用；更新關卡須重新驗證並發布新關卡版本。

## 流程

關卡載入與資料驗證 → 顯示操作提示 → 探索及互動 → 題目呈現 → 固定規則判定答案 → 提供已審核回饋 → 更新 localStorage 本機進度 → 檢查通關條件 → 顯示完成或重試選項。載入前須先檢查關卡及題目版本引用；遇到無效資料時拒絕載入關卡並提供可理解的錯誤，不可用未審題目繼續。

中斷或重新載入時，可使用已驗證的本機進度恢復；無效或版本不相容的資料應安全回退並通知使用者。

## 通關條件與 AI 權限

每關明確列出必需互動及最低答對條件。所有必需互動完成且答對數達標才通關；未達標時允許重試，且回饋不得洩漏未完成題目的未來答案。正確答案、計分、重複提交去重及通關狀態均由固定規則決定。

AI 不得決定或覆寫正確答案、得分、題目審查狀態或通關狀態。未來若接入 AI，只可提供非權威的輔助說明建議，須通過內容安全及故障回退處理；AI 關閉、不可用、逾時或回傳錯誤時，固定規則玩法仍須完整可用。

## 驗證與失敗處理

關卡 ID 唯一；互動 ID 唯一；題目引用的 ID／revision 必須存在且符合發布及審查門檻；單元與領域、關卡目標年級及題目年級範圍須相容；最低答對數不得大於可計分題數；資產路徑須存在並有使用授權。任何必填欄位、來源／題目引用或狀態驗證失敗，均拒絕關卡發布；執行時遇到無效引用則拒絕載入並記錄錯誤，不得將缺題視為已完成。

上述為規格要求。程式防護、錯誤呈現及自動化測試均尚待實作與驗證，不得由本文件存在推定已完成。
