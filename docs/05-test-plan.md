# 測試計畫與驗收標準

本文件是規格要求與未來驗收案例清單，不代表已有應用程式、驗證器或測試套件。本輪只修訂文件，未執行遊戲功能測試。

## 階段 0 文件驗收

- 必要文件清單為 README、docs/01–18 與兩份 `curriculum` JSON；文件存在不等於內容專業審查通過。`docs/18` 是單元登錄規格；本清單不表示實際單元登錄或永久 ID 歷史檔已建立。
- JSON 語法、必填欄位、來源 ID、單元 ID 及文件連結檢查須記錄實際結果；本測試計畫本身不是執行結果。
- 文件中的架構決策與專案原則一致；未將計畫、規格或候選題目誤述為已實作或正式核准。
- 未確認的課綱條目、教材進度及教師簽核須明確保留待審狀態與來源欄位。
- 階段 0 退出條件須同時符合本文件的文件／資料驗收及 `docs/10-stage0-signoff-checklist.md` 所列必要教育簽核；任一必要 EDU 項目未完成具名簽核時，階段 0 維持未通過，不建議進入階段 1。
- 遊戲、驗證器、部署與上述未來測試尚未執行時，必須如實標示未執行；不得以測試計畫存在宣稱通過。

## 階段 1 以後的驗收

待選定技術棧並實作後，新增對應單元、整合、瀏覽器及行動版測試。測試需覆蓋資料驗證、題目版本固定、保存升級、輸入、題目回饋、班級使用門檻、關卡完成、無障礙基本操作和部署預覽。階段 0 文件本身不等於這些功能已通過驗收。
