# 部署與回復計畫

本文件只規劃流程；目前專案沒有 Git repository 或應用程式，本次不部署、不推送、不建立 Git 設定。

## GitHub Pages（未執行）

1. 先由專案負責人建立/確認 repository、預設分支、建置命令及輸出目錄。
2. 在分支或預覽環境驗證建置產物、靜態路徑與 JSON 資料。
3. 確認 Pages 的 base path、HTTPS、錯誤頁及快取設定後，再由授權人員啟用部署。
4. 發布後檢查首頁、資產、手機版與瀏覽器主控台。

## Cloudflare Worker（未執行）

Worker AI 屬後續選配。先確認需求、模型可用性、費用/配額、隱私與資料保留政策。若採用，Worker 作為受控代理端，使用伺服器端秘密、輸入驗證、速率限制、逾時與固定規則回退；前端不可含秘密。部署前須有測試環境及可關閉 AI 的開關。靜態網站與 Worker 可分別部署，需記錄相容的 API 版本。

## 回復計畫

- Pages：將正式環境回退到上一個已知可用的 commit/部署版本，確認路由與資產快取更新；保留事故時間及版本記錄。
- Worker：保留上一個可用版本，透過部署版本回退或功能開關停用 AI 路徑；確認固定規則流程仍可使用。
- 課程資料：以版本控制回復有問題的 JSON，回復前確認題目/關卡引用一致；若保存結構改版，提供遷移或明確安全清除策略。
- 回復後執行首頁、題目、保存與關卡煙霧檢查並記錄結果。

任何正式部署或推送均需另有明確指示；本文件不構成部署授權。
