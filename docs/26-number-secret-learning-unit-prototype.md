# 「千位數的秘密」完整學習單元原型

## 用途與狀態

此原型把既有「千位數的秘密」三題練習延伸成目標介紹、視覺化概念教學、循序練習、錯誤診斷、對應補強、獨立候選檢核及回顧流程。內容和題目均為候選／待教師審查，不是正式課程、正式題庫或核准檢核。`M3-NUM-01` 仍是 `candidate`，Stage 0 仍為 `not_passed`。

完整學習單元資料位於 [`prototype/data/numberSecretLearningUnit.js`](../prototype/data/numberSecretLearningUnit.js)，流程狀態機位於 [`prototype/learningUnitFlow.js`](../prototype/learningUnitFlow.js)。由原本石碑入口進入後，可選「完整學習單元」；舊有三題挑戰仍可獨立啟動並沿用既有遊戲最佳成績、任務與徽章流程。

## 流程與證據

| 步驟 | 原型處理 | 證據界線 |
| --- | --- | --- |
| 目標與任務介紹 | 說明候選目標及示範狀態 | 不代表教師核定目標 |
| 概念教學 | 顯示 1,000 方塊，示範 1 個千、3 個千與千位 | 視覺示意，教材／年級適切性待審 |
| 循序練習 | 重用原有三題示範題 | 僅為候選練習反應，不是檢核 |
| 錯誤診斷 | 依候選錯誤類型提供原因說明與提示 | 一次選錯不作為學生診斷結論 |
| 補強活動 | 位置辨認、千的數量連結、數量合成三種對應補強 | 活動可操作，但教育內容待教師審查 |
| 獨立候選檢核 | 使用三個新情境候選題，不提供提示 | 結果只稱候選檢核結果；不是正式通過 |
| 回顧與下一步 | 分開顯示首次獨立答對、提示後答對、重試答對及錯誤次數，並列未覆蓋方向 | 不寫入學生章節進度，不判定目標達成 |

作答事件使用 session 內唯一 `submissionId` 與 `attemptId`，可拒絕重複提交；練習、補強及候選檢核分開。每次答題不會自動累加為多份正式檢核證據。完整單元流程只保存在記憶體，不讀寫 `localStorage`，不建立學生帳號或個人資料，也不修改舊遊戲進度。

## 目前可觀察範圍與缺口

- 數字與數量、千位意義：現有原型題及候選檢核可提供有限的選擇反應。
- 數的組成／拆解：原第三題涉及 2,000 與 500 的合成；其課綱支持與先備要求仍待審查。
- 多種表示法之間的轉換：尚未檢核。
- 0 作為佔位符：適用性維持待教師確認，未加入正式要求。
- 新情境遷移：只加入少量候選示例，不能據此證明遷移能力。
- 延後保持、跨情境穩定表現及章節整體掌握：未檢核。

現有追溯資料沿用 `mathematics`、`math-number-place-value-m3-num-01`、`N-3-1` 與第二學習階段表現 `n-II-1`。這只是專案既有資料參照，非本輪重新核對官方原文。年級／學期安排、教材版本及頁碼、實際授課、先備能力、教師審查和正式檢核門檻均未確認。不得把課綱代碼或遊戲完成視為上述證據。

資料中的 `scheduleAndEvidence` 明確保留空教材紀錄、空班級授課紀錄、未評估先備及空教師審查紀錄；這些空值表示尚無證據，不代表確認通過。
