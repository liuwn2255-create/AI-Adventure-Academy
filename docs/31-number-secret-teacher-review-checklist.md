# 「千位數的秘密」候選題目教師審查清單

## 1. 用途與目前狀態

- 文件用途：教師逐題審查第三版候選題，記錄證據、修改及決策；不是題庫，也不是核准紀錄。
- 對象：第三版藍圖 [`docs/30-number-secret-v3-candidate-question-blueprint.md`](30-number-secret-v3-candidate-question-blueprint.md) 中的八個草案代號。
- `DRAFT-M3-NUM-01-01` 至 `DRAFT-M3-NUM-01-08` 均為文件內追蹤代號，**不是正式題目 ID**。每題目前結果均為 `pending_review`；本文件未預填審查者、日期、同意或通過結論。
- `M3-NUM-01` 維持 `candidate`；Stage 0 維持 `not_passed`。
- 這份清單的完成，只代表相應文件欄位已填寫。教師審查、小規模教學試用、正式發布核准是不同階段；任何階段都不能由文件完成、程式測試、遊戲通關或星星數自動推定。

### 已核對資料邊界

- docs/27 記錄 `N-3-1` 為三年級學習內容範圍，並記錄 `n-II-1` 為第二學習階段表現；這不證明特定學期、目標班級已授課，亦不逐題核准本清單內容。
- `curriculum/learning-objectives.json` 的三項現有目標為候選、缺少教師核定的可觀察規準；其中 LO-03 涉及 `2,000` 與 `500` 合成，課綱映射及加法先備仍待審。
- `curriculum/learning-activity-map.json` 將現有三題標作原型練習、非正式檢核；候選活動仍待教師審查，且明列表徵互換、0 佔位、不同情境及正式檢核判準等缺口。
- `scripts/publication-guard.mjs` 提供題目／關卡發布前的引用及登錄驗證入口。它不會代替教師評估題幹、教學適切性或班級授課證據，也不會自動把本文件中的草案狀態轉為教師審查或試用結果。草案代號不得直接當成正式發布資料送入該入口。

## 2. 審查狀態與定稿階段

### 題目審查結果

每題必須單獨記錄一種狀態：

| 狀態 | 意義 | 可做事項／限制 |
|---|---|---|
| `pending_review` | 尚無完整逐題審查結論；本清單所有草案初始狀態。 | 可補證據、審題、提出修訂；不得視為同意或核准。 |
| `needs_revision` | 審查發現題幹、答案、先備、干擾項、提示、補強或證據需修改／補足。 | 記錄具體修改及依據；修改後重新審查相關項目。 |
| `approved_for_pilot` | 有權審查者在必要項目均有依據後，同意此版本僅進入受控小規模教學試用。 | 只允許明確範圍、對象及試用計畫；不等於正式發布或班級普遍適用。 |
| `approved_for_publication` | 題目內容審查及必要驗證完成，可申請正式發布審批。 | 仍需依正式發布流程確認單元版本、題目正式 ID／revision、來源、發布者及發布紀錄；本狀態本身不寫入正式題庫。 |

若缺少適用年級／班級進度、必要教材或先備證據，應維持 `pending_review` 或記為 `needs_revision`，不得選 `approved_for_pilot` 或 `approved_for_publication`。不適用項目需填「不適用」並說明理由，不能留白使其看似已通過。

### 四個不可混同的里程碑

1. **文件設計完成**：草案欄位、題幹和分析已整理；沒有教師核准含義。
2. **教師內容審查通過**：逐題必要項目由具適當角色的人員審查並留下依據；不代表試用完成、正式發布或適用所有班級。
3. **小規模教學試用完成**：依核准試用計畫收集去識別化的教學觀察及題目表現，並由教師解讀；不自動代表題目有效或可發布。
4. **正式發布核准**：依題庫發布規則完成單元／題目追溯、審查與發布者紀錄後，才由正式發布流程決定。發布也不等於任一指定班級已具備使用條件。

### 必審項目

對每題分別判定「通過／需修改／待確認／不適用（附理由）」並記錄依據：

- 課綱對應與主張界線；階段指標不得當作三年級單獨進度證據。
- 教材範圍與版本、實際授課證據及先備知識；三者各自記錄，不互相替代。
- 題幹、圖像／表格、數值、用語與閱讀負擔。
- 正確答案與解析。
- 每個干擾選項的合理性及其可能反映的策略；不可把假設寫成已驗證迷思。
- 提示是否洩漏答案，是否只用於練習而非獨立檢核。
- 補強活動是否針對可能錯因，且有不同教學操作而非只重做原題。
- 練習／補強／獨立檢核用途是否相符，以及與既有題目是否過度相似。
- 題目是否只測預定概念，或額外混入閱讀、加法、表格操作等未確認能力。

## 5. 題目定稿與發布決策流程

1. **先補必要證據**：取得實際教材版本、冊次、單元與頁次；由任課教師提供班級實際授課範圍、日期／週次及先備能力確認。出版社簡介或課綱表格不能替代班級紀錄。
2. **逐題初審**：題幹、正解、解析、每個干擾項、提示、補強、難度、語文負擔及課綱／教材對應逐項填表。任何必審項目待確認或需修改，不能進入核准狀態。
3. **版本修訂**：題幹、數值、選項、答案、解析、課綱／單元連結或教材證據有實質變更，保留原草案審查紀錄，建立新的草案修訂版本並重審受影響項目；不可直接覆寫舊審查結論。
4. **小規模試用**：只有狀態明確為 `approved_for_pilot`、有審查者／日期／依據、明確試用對象和計畫後，才能作受控試用。試用結果另行記錄，不把答對率自動解讀為題目有效或精熟。
5. **正式發布申請**：需先確認正式單元 `unitId` 與 `unitRevision` 可用、草案轉為正式題目 ID／題目 revision、必要課綱和教材證據、逐題內容審查、必要驗證及發布者紀錄。教師審查與發布者職責分開；核准題目也不自動適用任何班級。
6. **發布防護限制**：現有 `publication-guard.mjs` 只回報題目／關卡發布前的登錄與引用驗證錯誤，並要求呼叫端在錯誤非空時拒絕發布。未見其實作本清單四種教師審查狀態、試用紀錄或教學品質判斷；本文件不宣稱程式已支援這些工作流程，也不修改防護程式。
