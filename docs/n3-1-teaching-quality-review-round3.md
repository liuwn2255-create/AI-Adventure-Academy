# N-3-1「千位數的秘密」第二輪教學改善與候選題設計

> **狀態：候選設計，尚未教師審查或實作。**本文件及兩份 JSON 是教學審查材料，不是正式題庫、已核准評量、教學效度證據或學生精熟證據。`M3-NUM-01` 維持 `candidate`；Stage 0 維持 `not_passed`。錯答類型均為待驗證假設。

## 1. 範圍與資料來源

本輪依實際程式檢視：`prototype/data/numberSecretLearningUnit.js`、`prototype/data/numberSecretQuestions.js`、`prototype/data/teacherReviewCatalog.js`、`prototype/numberSecretV2CandidateFlow.js`、`prototype/teacherReviewRevisions.js`；並閱讀第一輪、第二輪審查報告、既有 N-3-1 課綱對照及 Stage 0 清單。另檢查原有備份 [`number-secret-round1-candidate-revisions.json`](../artifacts/number-secret-round1-candidate-revisions.json)，沒有修改它或載入／覆寫任何教師工作台資料。

現有教師目錄含 11 個千位數主項目：3 題循序練習、1 題 2,468 積木引導練習、3 題舊候選檢核、V2 Q1/Q2 可作答題、Q3 唯讀預覽、Q4 停用設計。另有 4 個實際可路由的舊補強活動；V2 Q1/Q2 仍標示 `remediationPolicy: not_provided`，第一輪 Q1/Q2 修訂中的補強文字也明確是未實作／未連結構想。

課綱狀態僅沿用專案文件已記載的 `N-3-1` 參照。本輪未重新取得或逐頁核對官方 PDF，因此不新增「本輪已核實」主張。`N-3-1` 可供位值題型作候選參照，但每題對應仍待審；中間 0 的精確教學範圍也待教師／課程專業人員核對。數的大小比較不直接套用 `N-3-1`，符合既有追溯稽核所記錄的限制。`n-II-*` 第二學習階段表現碼不能證明三年級特定學期進度。教材出版社、版本、冊別、頁碼及班級進度均待教師提供。

## 3. 新增候選題目

完整資料位於 [`number-secret-round2-candidate-items.json`](../artifacts/number-secret-round2-candidate-items.json)。共 4 題，均使用 `NS-R2-DRAFT-Q01` 至 `NS-R2-DRAFT-Q04`，狀態為 `candidate_pending_teacher_review`。每題資料包含題幹、選項、正解 ID、解析、獨立核算所需表示資料、能力、先備、兩層提示、錯答回饋、候選補強構想及教師問題。

| 題目 ID | 表徵／目標 | 正解 | 候選難度與限制 |
|---|---|---|---|
| `NS-R2-DRAFT-Q01` | 位值表；在 5,206 中判斷百位數字 2 代表的數量 | 200 | 中等；讀表先備待確認。欄位數字是題目條件，不把表格當作最終答案；避免另加顯示展開式的支架。 |
| `NS-R2-DRAFT-Q02` | 4,056 中間的 0 如何佔百位並保留 5、6 位值 | 「0 佔住百位，表示百位沒有百，讓 5 仍在十位、6 仍在個位」 | 較高；文字閱讀與零占位概念可能混合。教材是否教此說法、四位數與三位數比較先備待確認。 |
| `NS-R2-DRAFT-Q03` | 比較 3,042 與 3,402，說明由高位找第一個差異 | 3,402 | 較高；比較能力的正式課綱映射未確定，不指定 N-3-1；比較策略先備待確認。 |
| `NS-R2-DRAFT-Q04` | 由未按位序排列的積木數量描述組成含內部 0 的數 | 6,032 | 較高；將文字整理成位序，沒有圖表直接列出答案；積木單位與空位 0 先備待確認。 |

### 數學答案的獨立核算

使用候選題資料中的條件重新計算，不以原 `answerId` 作為推導：Q1 `2 × 100 = 200`；Q2 `4,056` 的百位為 0、十位為 5、個位為 6，省略中間 0 得到 `456`，各位值改變；Q3 千位相同，百位 `0 < 4`，故 `3,402 > 3,042`；Q4 `6 × 1,000 + 0 × 100 + 3 × 10 + 2 = 6,032`。新測試會由表示資料獨立導出預期結果，再核對所選選項及答案 ID。這只核對題目算術／結構一致，不證明教學有效或課綱適切。

所有干擾選項只連到假設性的錯誤策略；單次錯答不能確診學生迷思。提示與錯答回饋已寫在候選 JSON，但沒有接到 runtime。每題所列補強均是文字構想，狀態為 `candidate_proposal_only_not_implemented_or_linked`。

## 5. 審查建議順序與教師待決事項

1. 先提供實際教材出版社、版本／印次、冊別、單元、頁碼、學期及目標班級授課進度；確認學過的位名、位值表、積木、內部 0 與相關比較內容。
2. 審查 Q1 的表格欄位和「數字代表多少」用語，決定是否僅作引導練習。
3. 審查 Q2 的中間 0 解釋及文字閱讀負荷；確認百位空位與前後數字位值先備。
4. 由數學課程專業人員決定 Q3 適用課綱條目與單元歸屬；不以 N-3-1 自動對應。
5. 審查 Q4 的積木單位、口語描述及組數範圍，確認 0 占位是否已教。
6. 個別審閱 Q1/Q2 補強草案：是否採用卡片、使用何種新情境、如何記錄步驟與何時返回原題。教師逐題審查欄位保持空白，不預填決定。
7. 若教師接受設計，另決定是否需要小規模試用及匿名觀察方法；須以實際學生作答和口頭理由驗證，不以本輪數學核算或工程測試代替。

## 6. 驗證與狀態

本輪新增資料尚未接入正式題庫、遊戲、教師工作台或正式學習映射；Q1/Q2 補強草案也未接入。候選 JSON 和測試會檢查 schema 欄位、ID 唯一性／衝突、選項答案參照、獨立計算、提示不直接寫出正解及每題先備與限制欄位。沒有進行瀏覽器驗收，因沒有修改 UI 或 runtime。

候選設計不修改原始題目、原始錯答回饋、第一輪 JSON、正式學生進度、正式教師決定或活動解鎖。`V2-DRAFT-M3-NUM-01-03` 仍為唯讀預覽、`V2-DRAFT-M3-NUM-01-04` 仍停用。`M3-NUM-01` 維持 `candidate`；Stage 0 維持 `not_passed`。教材、課綱逐題對應、教學適切性及學生試用結果均未由本輪確立。
