### 實作條件判定

- **可先做不含學生使用的技術試作：**題 1、題 2；題 3 可先做資料呈現原型，但須以候選標籤及明確位值表檢核視圖隔離。這表示介面／流程可以工程實作，不表示內容已獲教師認可。
- **必須等待教師決定才能納入試用題組：**題 4。其展開表示與加法先備未確認，應設為明確停用的條件式候選。
- **四題共同限制：**教師需確認適用範圍、教材及班級授課證據後，才可決定是否進行小規模教學試用；沒有任何題目可由程式測試自動取得 `approved` 或正式發布狀態。

## 4. 最小實作順序與驗收條件

1. **凍結資料界線與教師前置決定**：確認教材版本／冊次／單元／頁次、實際授課範圍與 O1–O4 先備；題 4 另確認展開表示和加法。缺資料即保留待確認，題 4 不進入題組。
2. **建立 V2 候選資料而不替換舊題組**：保留四個草案代號於設計追溯欄，不當作正式題目 ID；資料記錄 `draftId`、題組版次、答案、解析、選項與審查狀態。驗收：schema／答案引用有效，題 4 gating 預設關閉，舊題目及舊識別完全保留。
3. **泛化檢核流程的題組選擇及結果記錄**：只在需要時加 `checkSetId`／版本參照；每次作答及彙總均保留題組歸屬。驗收：舊三題和 V2 題組分開作答與回顧，重試或重複提交不串題組、不重複計分。
4. **呈現與可及性**：題 1、2、4 使用單選；題 3 加上獨立檢核語意的位值表，無教學支架答案列；確認手機版不裁切。驗收：題面、選項、解析一致，鍵盤／觸控操作、返回地圖正常。
5. **回歸及治理檢查**：跑現有全套測試及相關學習流程測試，實際瀏覽器檢查新舊入口。驗收：候選標籤可見；新題組不改正式分數、星星、徽章、localStorage、正式學習進度、單元狀態或發布狀態；`M3-NUM-01=candidate`、Stage 0=`not_passed`。

## 5. 必須先由教師決定

- 目標班級實際教材出版社、學年度、版次／印次、冊別、單元、頁次及校本進度；不可用出版社公開簡介代替班級已授課證據。
- 本班是否已學 O1 位名順序、O2 位值數量、O3 位值表轉數字；若未教，決定是否只保留為教學示範而非檢核。
- 四題題幹、數值、選項、答案解析及預期作答方式是否清楚適切；干擾選項只是假設，是否有助觀察需教師與試做資料判斷。
- 題 3 的位值表是否符合該班教材表徵與學生熟悉方式。
- 題 4 是否納入；若納入，分開確認展開表示與加法／數量合成先備，並定義評分是否拆分。
- 是否試用、試用對象與觀察紀錄方式；如何保護學生資料；候選題的評分不可直接轉成正式精熟標準。

## 6. 可開始實作與尚不能核准

可開始的是**隔離的候選 UI／資料流程試作**：題 1、2 的單選呈現，題 3 的候選位值表呈現，以及新舊題組分流和自動測試。這是檢查工程可行性，不是允許作為正式課程或教師已核准的學生評量。

尚不能正式核准／發布的是全部四題與整個 `M3-NUM-01`：教材及實際授課證據、教師逐題審查、題 4 先備決定、必要試用證據與正式審查流程均未由本文件完成。程式通過只表示技術行為符合測試，不能替代教學效度審查。

本輪只新增本實作計畫；沒有修改遊戲程式、題目資料、正式課程資料或學生進度，沒有執行遊戲測試、部署或 Git 操作。

## 7. 候選試作整合更新

本節為後續工程整合紀錄；以上實作前計畫保留作為歷史基線。V2 題組目前只有題 1、題 2 位於可作答的隔離試作流程，維持 `candidate_pending_teacher_review`，結果只存在記憶體，並標示非正式評量。舊練習與原三題候選檢核保留原流程。

題 3（`V2-DRAFT-M3-NUM-01-03`）的題幹、四欄資料、選項、答案與解析依本文件第 4 節草案作成**唯讀、不可作答的預覽**。它不在 `questions` 作答集合內，不建立作答事件、不計分。預覽只用於檢視位值表版面；因讀表先備、教材表徵與實際班級進度尚未由教師確認，題 3 不得進入候選施測。

題 4（`V2-DRAFT-M3-NUM-01-04`）維持明確停用，未加入題組或畫面。啟用前必須取得展開表示與加法／數量合成的教材或實際教學證據、教師對評量構念及評分界線的書面決定，以及含審查者、日期、結論與依據的題目審查紀錄；條件不足時不得作答或納入試用。

候選試作工程測試只能證明隔離流程及 UI 資料行為符合預期，不等於教師審查、學生試用、教學效度、課程核准或正式發布。`M3-NUM-01` 仍為 `candidate`，Stage 0 仍為 `not_passed`。
